## 2026-09-14

### Week 2 · Day 3
1. Agent Loop 的本质：一个 while 循环 + 三条消息协议——现代 Agent 框架（Codex、OpenClaw 等）的循环骨架和这个没有本质区别，只是多了流式、多工具、记忆管理
2. 决策权的转移：从"你写 if 判断"（decide_tool）变成"LLM 通过 tool_calls 自己决定"
3. kwargs 解包：tool(**arguments)
4. 状态外置：Agent 不持有历史，run(messages) 纯粹是"处理这段对话"
现在agent类调用逻辑
外部调用 agent.run(messages)
    → 进入run()，进入while True循环
        → llm.chat拿到模型回复
        → 如果无tool_calls → return message → 回到外部代码，任务结束（message只返回最后一次回答，完整对话在messages列表）
        → 如果有tool_calls，进入for循环
            → result = self.execute_tool_call(tool_call)
                → 进入execute_tool_call
                    → 找到工具执行 return tool(**args)
                ← 回到run，赋值给result
            → append工具结果到messages
    → 回到while循环开头，再次调用llm.chat，新一轮思考
